EMAX ORDER PAGE SPEED FIX — INSTALLATION

IMPORTANT: Do not upload this ZIP directly into Supabase.

STEP 1 — CREATE THE NEW ORDERS TABLE
1. Open Supabase Dashboard.
2. Open your Emax project.
3. Click SQL Editor.
4. Click New query.
5. Open the file: supabase/orders-migration.sql
6. Copy all the SQL and paste it into Supabase SQL Editor.
7. Click Run.
8. You should see: Success. No rows returned.

STEP 2 — REPLACE YOUR LOCAL PROJECT
1. Back up your current project first using GitHub Desktop.
2. Extract this ZIP.
3. Copy all files from the extracted emax-auth folder into your existing project folder.
4. Choose Replace files when Windows asks.
5. Do not delete your existing .env or Vercel environment variables.

STEP 3 — TEST LOCALLY
1. Open the project in VS Code.
2. Open Terminal.
3. Run: npm install
4. Run: npm run dev
5. Open the Local link shown by Vite.
6. Open Order Tracking.

FIRST OPEN ONLY
- If the new orders table is empty, the website automatically copies your existing orders
  from app_storage into the new orders table.
- Do not close the browser during this first migration.
- After it opens, check Supabase > Table Editor > orders.
- You should see one row for each order.

STEP 4 — CHECK THESE ITEMS
1. Existing orders appear.
2. Open an order.
3. Edit a small remark and save.
4. Refresh the page and confirm the change remains.
5. Create one test order.
6. Delete the test order.
7. Confirm Previous / Next pagination appears when there are more than 25 matching orders.

STEP 5 — PUBLISH
1. In GitHub Desktop, commit with message: Optimize order storage and pagination
2. Push origin.
3. Wait for Vercel deployment to complete.

WHAT CHANGED
- Each order is now stored as one Supabase row instead of one giant JSON record.
- Saving one order updates only that order.
- Bulk actions update only changed orders.
- The list renders only 25 order cards per page.
- Existing order data is migrated automatically after the SQL table is created.

ROLLBACK
- Your old app_storage order record is not deleted.
- To roll back, restore your previous GitHub commit.
